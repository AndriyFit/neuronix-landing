# AGENTS.md — правила для агентів у цьому репозиторії

## Найголовніше: тут працюють ДВА агенти

**Claude Code** (гілки `claude/*`) і **Codex** — одночасно, з різних машин,
**не бачачи одне одного**. Спільного каналу зв'язку між нами не існує: ні один
агент не отримує сповіщення про те, що робить інший, поки сам не подивиться.

Наслідок, з якого випливає все решта: **єдина точка синхронізації — цей
репозиторій і GitHub**. Те, чого немає в комітах, PR або документації, для
другого агента не існує. Рішення, ухвалене в чаті й не записане сюди, буде
скасоване другим агентом при першій же правці — не зі зловмисності, а тому
що він про нього фізично не знає.

## Перед тим як зробити хоч одну правку

Це не формальність. Обидва агенти вже наступали на те, що правили код,
не знаючи про рішення, ухвалене годину тому.

```bash
git fetch origin
git log --oneline -15 origin/main          # що змінилось, поки тебе не було
git status                                  # чи не лишив хтось незакомічене
```

1. **Прочитай `CLAUDE.md` повністю.** Це джерело правди проєкту: ухвалені
   рішення, чому саме так, і перелік пасток, на які вже наступали. Там багато
   позначок ⚠️ ЗАСТАРІЛО з датами — вони показують, що саме змінилось і коли.
   Не «проглянь по діагоналі»: половина файлу існує тому, що хтось уже зробив
   помилку, яку там описано.
2. **Подивись відкриті PR.** Якщо там висить незмерджена робота, яка чіпає ті
   самі файли — спершу з'ясуй, що з нею, а не працюй паралельно.
3. **Подивись активну спеку** в `docs/superpowers/specs/` — найсвіжішу за
   датою. Там розписано, який етап зроблено, який ні, і які рішення чекають
   на власника.
4. **Подивись гілку іншого агента**, якщо вона є:
   `git log --oneline -10 origin/<гілка>`.

## Цей файл НЕ дублює CLAUDE.md

Свідомо. У цьому проєкті дублювання фактів уже тричі призводило до розбіжності
(ціни в json проти оголошень, проти промпту агента). `AGENTS.md` описує **як
двом агентам не заважати одне одному**, `CLAUDE.md` — **що ми вирішили і чому**.
Правила проєкту, стек, конвенції, пастки — усе там, і читати треба саме там.

## Файли, де конфлікт найімовірніший

| Файл | Чому небезпечно |
|---|---|
| `src/i18n/uk.json`, `en.json` | Один величезний файл, який чіпає майже будь-яка зміна контенту. Git зіллє його синтаксично правильно, а зміст поїде — конфлікт буде **мовчазним**. Файли ще й мусять лишатись дзеркальними за структурою |
| `CLAUDE.md` | Обидва агенти дописують сюди після роботи |
| `package-lock.json` | Регенерується цілком; зливати руками не можна — тільки `npm install` заново |

Збираєшся правити щось із цього — спершу переконайся, що інший агент не в
процесі. Найдешевший спосіб: подивитись його гілку і відкриті PR.

## Гілки

- **Ніколи не пушити в гілку іншого агента.** Claude працює на `claude/*` і
  **робить там force-push** при перезапуску гілки від `main` — твої коміти в
  такій гілці зникнуть без сліду й без попередження.
- Своя робота — своя гілка, свій PR у `main`.
- `main` захищений здоровим глуздом: тільки через PR, тільки із зеленим CI.

## Як лишити повідомлення другому агенту

**Коментар у PR або GitHub issue.** Асинхронно, з часовою міткою, обидва
можуть читати й писати, і — головне — це не створює конфліктів злиття.

Файл-«журнал» у репозиторії для цього НЕ заводимо: кожне повідомлення стало б
комітом, а два агенти, що пишуть в один файл, отримали б конфлікти рівно там,
де мали б координуватись.

## Перед пушем — прогнати повний ланцюг

Той самий, що й у CI. Локально зелений ланцюг = зелений CI.

```bash
npm ci                                     # саме ci, не install
npm run lint                               # 0 errors; warnings очікувані
npm run typecheck
npm test
npm run build
python3 docs/ai-agent/check-prompt-facts.py
```

Правив ціни або тексти — `npm test` тепер це ловить: `src/lib/prices.test.ts`
падає, якщо в json з'явилась сума, якої немає в `pricing.items`.

## Після роботи — записати рішення в CLAUDE.md

Не звіт «що я зробив» — це видно з git. Записуй те, чого з коду не видно:
**чому саме так, які варіанти відкинуто і на що не наступати наступного разу.**
Побачив, що якесь твердження в `CLAUDE.md` стало неправдою через твою ж
правку — виправ його там же. Документація, що описує стан «до», гірша за її
відсутність: другий агент їй повірить.
